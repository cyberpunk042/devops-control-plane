> Date: 2026-03-18

## The Big Picture

After E9-E11, modules have:
- ✅ Intelligent upgrade/downgrade checklists
- ✅ Automation engine (49 handlers, 82% coverage)
- ✅ Dep pinning + compatibility checking
- ✅ Code feature scanning + __future__ remediation
- ✅ pyproject.toml generation
- ✅ Wizard flow with streaming + remediation

What they DON'T have:
- ❌ Own test files (all 108 tests are in root `tests/`)
- ❌ Ability to test against the TARGET Python version
- ❌ Own venv for isolation
- ❌ Posture awareness of test coverage per module
- ❌ Scaffolded test structure

The gap: you complete a compatibility plan, the system says "done," but there's
no way to actually VERIFY the module works on the target Python. The test step
runs pytest on 3.12 and calls it a day.

## The Evolution: 5 Capabilities

### Capability 1: Detect Per-Module Test Status

**What:** Posture shows test coverage status per module.

**Categories:**
- **Has own tests** — test files exist in/for this module directory
- **Tested via parent** — root `tests/` has tests that import from this module
- **No tests** — no test files found for this module

**How to detect:**
1. Scan module directory for `test_*.py` or `*_test.py` files
2. Scan root `tests/` for files that import from the module's package
3. Use `test_inventory()` to get the full picture

**Posture display:**
```
core    python-lib    ≥3.8    ...    🧪 Parent only
web     python-flask  ≥3.8    ...    🧪 No tests
cli     python-cli    ≥3.8    ...    🧪 Has own tests
```

The 🧪 indicator links to detail showing:
- How many test files / test functions
- Which framework detected
- Coverage percentage (if available)
- "Scaffold tests" button

### Capability 2: Scaffold Module Tests

**What:** Generate a basic test structure for a module that has none.

**Uses:** `generate_test_template(root, module_name, stack)` — already exists!

**What it generates:**
```
src/core/
├── tests/
│   ├── __init__.py
│   ├── conftest.py          ← module-level fixtures
│   └── test_smoke.py        ← basic import + sanity tests
```

**test_smoke.py content:**
```python
"""Smoke tests for the core module.

Verifies basic imports work and critical entry points are callable.
Auto-generated by the DevOps Control Plane.
"""

def test_module_imports():
    """Verify the module can be imported without errors."""
    import src.core  # noqa: F401

def test_version_floor():
    """Verify we're running on the expected Python version."""
    import sys
    assert sys.version_info >= (3, 8), f"Expected Python >=3.8, got {sys.version_info}"
```

**conftest.py:**
```python
"""Module-level test fixtures for core."""
from pathlib import Path
import pytest

@pytest.fixture
def module_root():
    """Path to this module's directory."""
    return Path(__file__).parent.parent
```

**Trigger points:**
- Plan step: "Scaffold module test structure"
- Posture: "No tests" indicator → "Scaffold tests" button
- Remediation modal: "Create tests" option

### Capability 3: Test Against Target Python Version

**What:** Create a venv with the target Python and run tests in it.

**Prerequisites:**
- Target Python binary available on system (e.g., `python3.8`)
- Module has pyproject.toml or requirements.txt
- Module has test files

**Flow:**
```
1. Check: is python{target} available?
   → shutil.which(f"python{target}")
   → If not: show "Python {target} not available. Install with pyenv."

2. Create temp venv:
   → python{target} -m venv .venvs/{module}-{target} --clear

3. Install module deps:
   → .venvs/{module}-{target}/bin/pip install -r requirements.txt

4. Run tests:
   → .venvs/{module}-{target}/bin/python -m pytest {module_path}/tests/ -v

5. Report results:
   → Stream output live via wizard
   → Parse: passed/failed/errors/skipped
   → Show: "3 passed, 1 failed on Python 3.8"
```

**This is a REAL compatibility test.** Not "run on 3.12 and hope." Actually testing
on 3.8 to verify the compatibility claim.

**Venv location:** `.venvs/{module}-{target}/` — gitignored, ephemeral.

### Capability 4: Default Test Generation

**What:** Generate smarter default tests beyond just smoke tests.

**Types of auto-generated tests:**

**Import verification tests:**
```python
def test_all_submodules_importable():
    """Verify every .py file in the module can be imported."""
    import importlib
    from pathlib import Path

    module_root = Path("src/core")
    for py_file in module_root.rglob("*.py"):
        if py_file.name.startswith("_"):
            continue
        module_path = str(py_file.relative_to("src")).replace("/", ".").replace(".py", "")
        importlib.import_module(f"src.{module_path}")
```

**Public API tests:**
```python
def test_public_api_exists():
    """Verify declared public API is accessible."""
    from src.core.services.module_upgrade import generate_checklist
    assert callable(generate_checklist)
```

**Version compatibility tests:**
```python
def test_no_runtime_features_above_floor():
    """Verify no runtime code features exceed the declared floor."""
    # This test FAILS if someone adds match/case to a 3.8-targeted module
    import ast, sys
    # ... scan .py files for version-specific AST nodes
```

**Dependency import tests:**
```python
def test_declared_deps_importable():
    """Verify all declared dependencies can be imported."""
    deps = ["flask", "pydantic", "pyyaml"]  # from pyproject.toml
    for dep in deps:
        __import__(dep)
```

## Decisions (Locked)

1. **Venvs:** User's choice. Offer cleanup after testing or leave it. No forced policy.
   Location: `.venvs/` or system Python — user decides. If system Python is fine, use it.

2. **Test location:** Module-level tests (`src/core/tests/`) as primary.
   ALSO offer (checked by default) to add corresponding tests to parent `tests/` directory.
   UX: "☑ Also add to parent tests/ (integration coverage)" with explanation of what
   checking/unchecking means.

3. **Target Python not found:** Use the existing tool_install + remediation system.
   "python3.8 not found" → detect available install methods → show install plan.
   User can also choose system Python if it matches or is acceptable.

4. **File creation:** Never auto-commit. Create files, show preview, user confirms.

## Full Evolution Plan

### Chunk 1: Per-Module Test Detection + Posture Indicator

**Goal:** Posture knows if each module has tests.

Steps:
1. For each module, scan for test files:
   - In module dir: `{module_path}/tests/`, `{module_path}/test_*.py`
   - In root `tests/`: files that contain `import src.{module_package}` or `from src.{module_package}`
2. Add `test_status` to posture enrichment:
   - `"own"` — has test files in module directory
   - `"parent"` — root tests/ imports from this module
   - `"none"` — no tests found
   - `"count"` — number of test functions
3. Show 🧪 indicator in posture table
4. Peek panel: test detail (how many, where, "Scaffold tests" button if none)

**Files:**
- `bridges/modules.py` or `posture.py` enrichment — add test detection
- `_system_posture.html` — 🧪 indicator + peek panel

### Chunk 2: Test Scaffolding Modal

**Goal:** Generate test files for a module that has none.

Steps:
1. Modal with pre-filled info:
   - Module name, stack, import paths
   - Preview of generated test files
   - ☑ "Add to module tests/" (always checked)
   - ☑ "Also add to parent tests/ (integration)" (checked by default)
   - Explanation of what each option means
2. Generate files:
   - `{module}/tests/__init__.py`
   - `{module}/tests/conftest.py` — module fixtures
   - `{module}/tests/test_smoke.py` — import verification, version check
   - Optionally: `tests/test_{module}_integration.py` in root
3. Uses existing `generate_test_template()` as base, extends with smarter content
4. Preview modal → confirm → write files (never commit)

**Triggers:**
- Plan step: "Scaffold module tests" (new recipe step)
- Posture "No tests" indicator → button
- Remediation modal → option

### Chunk 3: Target Python Detection + Venv Setup

**Goal:** Test on the actual target Python version.

Steps:
1. Detect available Python versions:
   - `shutil.which(f"python{target}")` for the plan target
   - List all `python3.*` binaries found
   - Check if venv module is available for that Python
2. If target Python not found:
   - Use tool_install system: show install plan for Python {target}
   - Or: offer to use system Python with a warning
3. If found: offer venv creation
   - User choice: create `.venvs/{module}-{target}/` OR use system Python
   - If venv: `python{target} -m venv .venvs/{module}-{target}/`
   - Install deps: `.venvs/.../bin/pip install -r requirements.txt`
4. All via wizard modal with streaming output

**New plan step:** "Set up test environment for Python {target}"

### Chunk 4: Isolated Test Execution

**Goal:** Run tests in the target environment via wizard.

Steps:
1. Updated test step in recipe:
   - If target venv exists: use it
   - If system Python matches target: use it
   - Otherwise: warn about mismatch
2. Wizard streams test execution:
   - Shows each test file being run
   - Parses pytest output (pass/fail/skip counts)
   - Shows failures inline with tracebacks
   - Final summary: "12 passed, 1 failed, 3 skipped on Python 3.8"
3. Test results stored (optional) for posture display

### Chunk 5: Smart Test Generation

**Goal:** Auto-generate meaningful tests based on module analysis.

Test types:
1. **Import verification:** every .py file in module can be imported
2. **Public API:** every function/class in `__init__.py` is callable
3. **Version compatibility:** no runtime features above declared floor
4. **Dependency imports:** all declared deps are importable
5. **Basic instantiation:** models/classes can be constructed with defaults

All generated with a preview modal. User can edit before saving.

### Chunk 6: Posture Deep Integration

**Goal:** Test status as a first-class posture dimension.

- Module posture row shows test status alongside floor/deps/code
- Test findings (no tests, failing tests, uncovered code) as posture warnings
- Plan steps auto-generated based on test gaps
- Test coverage tracked over time (optional, stored in .state/)
